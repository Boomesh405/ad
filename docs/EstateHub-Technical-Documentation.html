1. Project Overview

EstateHub is a full-stack real-estate property management and transaction platform designed for the Indian market. It enables property owners/agents to list properties, buyers/tenants to search and book properties, and administrators to moderate listings — all with integrated payments (Razorpay) and digital agreement signing (Digio).

Core Features

  • Property Listings: Create, search, and browse properties with advanced filters (city, type, price, possession status, listing type for sale/rent)
  • Role-Based Access Control: Four distinct roles — Super Admin, Builder/Owner, Agent, Buyer/Tenant — each with tailored UI and permissions
  • Booking System: Token-based booking with Razorpay payment integration and webhook-confirmed status updates
  • Lease Agreement: Digital agreement execution via Digio eSign with webhook-based status tracking
  • Admin Moderation: Approve/reject listings with reasons, view all listings by status
  • Sale vs Rent: Properties explicitly tagged as FOR_SALE or FOR_RENT with appropriate pricing display
  • Property Media: Photo gallery with cover photo selection for each listing
  • CRM Integration: Lead management with enquiry tracking, stages, scores, and follow-up notes
  • Rate Limiting: Configurable rate limits for enquiries and searches

Request Flow

  1. Client Request: React SPA sends HTTP request with JWT Bearer token to Vite proxy
  2. Proxy: Vite dev server forwards /api/* requests to Spring Boot on port 8080
  3. Security Filter: JwtAuthFilter intercepts request, validates JWT, extracts user ID and role
  4. Authorization: @PreAuthorize annotations check role/ownership permissions
  5. Controller: Validates input (@Valid), delegates to service layer
  6. Service: Business logic, transactions, cross-cutting concerns
  7. Repository: JPA queries via Spring Data + JpaSpecificationExecutor for dynamic search
  8. Response: JSON response returned through the same chain

5. Authentication & Authorization

JWT Authentication Flow

  1. Register: POST /api/v1/auth/register — creates user, hashes password (BCrypt cost 12), returns JWT access + refresh tokens
  2. Login: POST /api/v1/auth/login — validates credentials, returns JWT pair
  3. Token Structure: HS512-signed JWT containing uid (UUID), role, sub (mobile), iat, exp
  4. Access Token: 1-hour expiry, sent as Authorization: Bearer <token>
  5. Refresh Token: 7-day expiry, type="refresh" claim, used to obtain new access tokens
  6. Filter Chain: JwtAuthFilter runs before every request, validates token, sets SecurityContext

Ownership Enforcement

Beyond role checks, the service layer enforces ownership:

  • Booking cancellation: Only the booking's buyer can cancel
  • Property activation: Owner/agent may only activate their own listings (unless admin)
  • Booking confirmation: Only reachable via Razorpay webhook (no public endpoint)
  • Agreement execution: Only reachable via Digio webhook (no public endpoint)

8. Webhook Integrations

Razorpay (Payments)

When a buyer places a booking, a Razorpay order is created. Upon successful payment, Razorpay sends a payment.captured webhook:

  1. Webhook arrives at POST /api/v1/razorpay/webhook
  2. RazorpayWebhookController verifies HMAC-SHA256 signature using RAZORPAY_WEBHOOK_SECRET
  3. On valid payment.captured event: updates booking status to CONFIRMED, sets property status to BOOKED
  4. Generates a booking slip (PDF) and stores reference in S3

Digio (eSign Agreements)

After booking confirmation, a lease/sale agreement is created via Digio. When all parties sign:

  1. Webhook arrives at POST /api/v1/digio/webhook
  2. DigioWebhookController verifies HMAC-SHA256 signature using DIGIO_WEBHOOK_SECRET
  3. On valid signed event: updates agreement status to EXECUTED, stores signed PDF reference

Security Note

Critical: Booking confirmation and agreement execution are only reachable via webhook endpoints — there are no public confirm/execute API endpoints. This prevents unauthorized status manipulation.
